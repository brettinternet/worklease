Callers that claim opaque keys get an unreadable list. `bl` claims `coordination:generic:<sha256>`, which the claims TUI cuts to `coordination:generic:dd8f85eb…` (`internal/claimsui/claims_view.go` shortResource) and `worklease list` prints the same way (`internal/cli/text.go` writeListTextAt). The readable label the caller passed with `--work-key` (for example `github.com/brettinternet/backlog BL-76`) appears only in the TUI detail pane and in `status --full`, never in either list.

Worklease stays naive about callers: the rule is generic. A caller-supplied work key is the human label, so it wins in list views. The default work key (resources joined) adds nothing, so those claims keep the resource summary. No schema or protocol change: `workKey` is already public, retained per epoch, and returned by list.

Related: backlog BL-80 makes `bl` send a project-qualified work key. WL-172 covers richer public attributes; this task does not depend on it.
