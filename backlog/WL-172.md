Users want to find the coding-agent session (and similar context) that worked a given item. Claim epochs already retain agentId, sessionId, and workKey, and agent instructions ask harnesses to pass their own loop-run ID as the session. Two gaps remain: when no selector is given, Worklease generates the claim sessionId, so it is not the harness session; and there is nowhere to record other non-secret associations such as the harness name, transcript reference, worktree, or PR URL. The checkpoint is the wrong home: it is private recovery metadata, overwritten on every write, and redacted from public views. Task trackers such as `bl` would read these associations through the `--json` claim CLI. This changes the claims/epochs schema, Remote Authority Protocol V1, and the redaction rules in docs/claim-model.md, so only the first criterion (a harness-supplied session ID) should proceed now; attributes wait for demonstrated need.
