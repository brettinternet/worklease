Users want to find the coding-agent session (and similar context) that worked a given item. Claim epochs already retain agentId, sessionId, and workKey, and agent instructions ask harnesses to pass their own loop-run ID as the session. Two gaps remain: when no selector is given, Worklease generates the claim sessionId, so it is not the harness session; and there is nowhere to record other non-secret associations such as the harness name, transcript reference, worktree, or PR URL. The checkpoint is the wrong home: it is private recovery metadata, overwritten on every write, and redacted from public views. Task trackers such as `bl` would read these associations through the `--json` claim CLI. This changes the claims/epochs schema, Remote Authority Protocol V1, and the redaction rules in docs/claim-model.md, so only the first criterion (a harness-supplied session ID) should proceed now; attributes wait for demonstrated need.

## Acceptance criteria

- [ ] Before designing, record whether requiring harnesses to supply their own session ID (closing the generated-sessionId gap) meets the need without new attributes; if so, implement only that and close this task
- [ ] If attributes are needed: a bounded set of non-secret key/value attributes can be supplied at acquire time (CLI and MCP), with documented key syntax, count, and size limits enforced by the authority
- [ ] Attributes are retained with the claim epoch and returned by status and resource history for both local and remote authorities
- [ ] docs/claim-model.md defines attributes as public, non-secret metadata, and Remote Authority Protocol V1 is updated for the new fields
- [ ] Tests cover limits, retention after release, and remote round-trip

## Notes

Evidence from bl (2026-10-23): claims bl creates were hard to identify, but the existing public workKey covers it. bl will send a project-qualified work key (backlog BL-80), and WL-174 shows caller work keys in list and TUI. A checkout or worktree path is not a good attribute for identifying a claim: it is host-local and wrong on a shared remote authority. This is not demand for attributes; the first criterion's question stays open.
