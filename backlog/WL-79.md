Coding agents commonly mutate repositories through native edit and shell tools rather than through `worklease exec` or `replace-file`. A caller needs a cheap, non-mutating way to prove that its private lease handle still possesses the current unexpired ownership epoch immediately before such a mutation, while preserving Worklease’s truthful coordination-only boundary.

## Acceptance criteria

- [ ] A CLI command and supported public API verify a private lease handle against the current claim, including claim identity, bearer credential, revision, expiry, and expected singleton or ordered bundle resources.
- [ ] Successful verification does not change the claim revision, expiry, checkpoint, operation history, or retained lifecycle history.
- [ ] Missing, expired, stale, mismatched, and invalid-credential handles fail with stable machine-readable reasons and actionable text output.
- [ ] Verification output and failures never expose bearer tokens, token hashes, checkpoint bodies, or lease-file contents.
- [ ] Documentation states that verification is a cooperative precondition check, not an atomic fence around a later direct edit or provider mutation.
- [ ] Tests cover singleton and bundle success, every failure class, redaction, and the absence of state mutation.

## Plan

1. Add a dedicated read-only verification request/result API that reuses current-claim validation without exposing secrets or mutating state.
2. Add one handle-driven verify CLI command for singleton and ordered bundle handles, including contextual defaults, stable diagnostics, text output, and schemas.
3. Document verification as a cooperative precondition rather than an atomic fence.
4. Add store, CLI, schema, redaction, and non-mutation tests; run review and all quality gates.
