## Why

Text-mode contention errors print the holder as a raw Go map, the first thing a person sees when a resource is busy:

```text
error: already-claimed: resource is already claimed
holder: map[agentId:brett claimId:74c8290176c366da16ae86487ea585d4 expiresAt:2026-11-17T18:15:58.560033Z resources:[task:demo] sessionId:a workKey:task:demo]
```

`internal/output/output.go` writes nested values with `fmt.Sprint`.

## Shape

- Render the holder as readable text, consistent with `status` and `list`: work key, agent, session, short claim ID, and relative expiry.
- Fix nested-value rendering in text output generally if other fields show the same problem, rather than special-casing one command.

  Evidence: Holder text is built from redactHolder projection and passed through escapeText; TestHolderProjectionKeepsOnlyBoundedPublicFields (injected newline dropped) and redaction test (no secret, empty holder line omitted) pass; mise run lint/format-check/test clean.
