Plan section 14 ("Bounded work") needs one scheduler per process. It shares budgets per provider quota identity (for GitHub, host plus account), cancels superseded reads, deduplicates in-flight fetches, and reserves capacity for authoritative action checks. Priorities are action checks, then selected detail, then visible page, then background. Claim heartbeats must never wait behind it: they run on a separate control path (plan section 9, "Who renews a claim?"), which WL-130.2 relies on.

This scheduler replaces the minimal per-account serialization added in WL-128.5, and it also bounds Backlog.md subprocess concurrency (at most 4 processes per source).

## Acceptance criteria

- [x] A scheduler keyed by quota identity runs GitHub requests serially per host and account within the process and runs Backlog.md processes with at most 4 concurrent per source, in priority order: action check, selected detail, visible page, background
- [x] Superseded reads are cancelled, duplicate in-flight fetches are coalesced, and pending jobs are capped with a structured overload diagnostic
- [x] Capacity is reserved so that an action check never waits behind background hydration
- [x] Rate-limit state (retry-after, reset time, and secondary limits) is shared per quota identity and surfaced as `rate-limited` with a retry time, separate from offline
- [x] GitHub mutations, when S6 adds them, are spaced at least 1 s apart per quota identity. The scheduler exposes this spacing now, and tests cover it
- [x] Uncertain writes are never retried. The scheduler retries only operations marked safe
- [x] Documentation and diagnostics never claim cross-process quota coordination. Aggregate load from several partitions or processes sharing an account is handled with jitter and backoff, and WL-129.6 measures it
- [x] Tests with a fake clock and fake adapters cover priority inversion, cancellation, coalescing, overload, and rate limiting
