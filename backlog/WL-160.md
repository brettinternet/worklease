Hosted authorities can restore an owner-supplied SQLite backup through `server restore`, but Worklease ships no verified way to create one. docs/container.md only says to use "a supported online SQLite backup or replication integration" and does not name or test one. An operator who copies the live database file without its WAL can end up with a backup that cannot be restored.

Start with the simplest option: document and drill one external online-replication tool (for example Litestream) against S3-compatible storage, feeding the existing recovery-mode restore. Build backup support into Worklease only for gaps the drill records, such as scheduling, retention, artifact verification, or recording the durable cutoff. This is disaster recovery, not high availability (see WL-166).

## Acceptance criteria

- [x] docs/container.md documents one tested online-backup recipe for S3-compatible storage that keeps credentials and replica state outside the authority home
  Evidence: aae2cf3: docs/container.md 'Online backup with Litestream' (Litestream 0.5.17 to S3; s3.env in /etc/litestream, meta-path /srv/worklease/litestream outside the home). Recipe exercised by mise run backup-drill against SeaweedFS S3; drill asserts no Litestream state in the home. mise run doc-test passed.

- [x] A drill restores that backup through worklease server restore, enters recovery mode, and records the selected durable cutoff; the drill evidence is retained
  Evidence: mise run backup-drill (scripts/drill-hosted-backup.sh) passed: replicate, lose unreplicated tail, delete home, litestream restore -integrity-check full, server init + server restore; recovery status recoveryMode=true; selectedDurableCutoff 2026-10-24T04:57:33.981815Z == replicated claim acquiredAt; replicated claim endReason=restored; lost resource has no epochs. Evidence retained at ~/.cache/worklease-drill/worklease-backup-drill.r4YffZ/evidence (summary.txt).

- [x] The item records which gaps (scheduling, retention, verification, cutoff recording) the external recipe leaves; built-in backup support is added only for those gaps
  Evidence: Gaps recorded in docs/container.md table and item note: scheduling (covered: continuous replication), retention (covered: Litestream retention/compaction), verification (covered: -integrity-check full, restore schema checks, periodic drill), cutoff recording (gap: LTX times are upload times truncated to seconds). Only built-in addition: server restore defaults/reports selectedDurableCutoff from the backup's last committed write; TestHostedRestoreDefaultsCutoffToBackupLastWrite passed -race -count=3.
