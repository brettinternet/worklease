## Why

The claims TUI shows who holds a resource but not whether that agent is still alive or how to reach it. A held claim can outlive its agent (a heartbeat wrapper keeps renewing it), so liveness next to the claim helps a person decide whether to wait, message the holder, or check for a stale claim.

## Shape (draft, decide after bl's resolver ships)

- On the claims detail view, resolve the holder's `sessionId` and `agentId` to live channels (Herdr pane, Claude Code peer name), off the render loop, and show status plus handle. No new claim fields: everything comes from the session ID (see the session ID guidance item).
- bl implements the resolver first, in `internal/contact`. bl doesn't import Worklease's Go module, so decide then whether to copy the small resolver or move it into a shared public package. Don't build a second design.
- Read-only. The TUI never messages agents itself.

## Plan

Decision (2026-10-29, with owner): copy bl's built-in herdr and claude-peer resolvers from bl internal/contact (e8d8c8b) into a Worklease internal package; skip user-config resolvers (they depend on bl hooks helpers and contact: config).
